# DS4.1 v1.1.43 on four RTX 4090s: 8192 and 5120 prompt chunks

Measured 2026-10-31. This is an optional tuning case study. The original 8192 configuration was restored; no default change or production promotion is proposed.

Two Xeon Platinum 8380 sockets (80 physical cores / 160 threads), about 251.3 GiB physical memory, four RTX 4090s (24,564 MiB each) at 265 W, Ubuntu 24.04.4 LTS, NVIDIA driver 595.99.02, CUDA compiler 13.0.88 / sm_89. Model: DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ2_XXS; Engram in RAM. Native parallel 8, context 262144; requested TP2 becomes effective single-device layer groups.

The same stock binary, frozen startup profile, lane-calibration seed and synthetic payloads were used for A1=8192, B=5120, A2=8192. Per-arm session storage was isolated. Performance inputs reused zero prefix tokens; model loading was outside the timings. Main lengths each use three different fixed inputs, not statistical repetitions. Each main/boundary output is 256 tokens.

Rates are per-arm medians. Percentages are the median of matching-case ratios, so dividing the displayed medians need not reproduce the percentage. Every individual ratio and both control directions are in the numeric companion.

At 8K, median effective TTFT was 5.242 / 3.478 / 5.267 seconds. At 32K it was 9.943 / 8.341 / 9.943 seconds. Prefill gains were present against both controls; 32K decode has about 6.6% paired A/A drift and must not be described as a reliable decode gain.

The 5121/6000-token single boundary inputs improved paired native Prefill by 41.44% / 42.95%. A single fixed input at each boundary cannot establish a general boundary result.

Each arm also completed one eight-client cold 4K batch: aggregate output throughput including cold Prefill was 34.24 / 34.08 / 34.04 tok/s (shared makespan 29.91 / 30.05 / 30.08 seconds). This is roughly unchanged and is not steady-state decode throughput, a capacity result, or p95.

All 93 test dispatches reconciled: 90 completed SSE streams and three intentional disconnects, including three excluded warmups. JSON, forced tool, mock tool-result and cancellation/resume checks passed. The approximately 16K resume prompts each reused 16397 of 16398 input tokens, with effective TTFT 118.6 / 105.8 / 116.1 ms. These are narrow synthetic contracts, not broad business-quality acceptance.

Startup GPU resident experts summed to 7729 / 8049 / 7729. Smaller prompt buffers changed expert placement as well as chunking. Dynamic routing/generated text was not held identical: 16 of 17 main/boundary A1/A2 text hashes differ, and every B text differs from both controls. No numerical/output-equivalence claim is made.

The [numeric companion](ds41-four-4090-v1143-chunk-20261031.json) contains all 93 records, actual token counts, native/client timings, cache evidence and hashes. The [compressed synthetic input corpus](ds41-four-4090-v1143-chunk-20261031-inputs.json.gz) contains the exact payloads and case order, including all eight batch payloads. It has no network transport or authentication.

For reproduction, pin the source commit, model/quant, hardware/power, stock binary and startup seeds; follow the sanitized native argument template in the JSON, replace only --prefill-chunk, isolate session directories and preserve the recorded input order. Request results must confirm actual input/output counts and zero prefix reuse. Use one shared makespan for each concurrent batch. Re-measure on other hardware; do not add this HTTP protocol to the official speed tables.

This evidence supports optional documentation for this configuration. It does not justify changing the global default. It lacks broad quality, 128K/near-256K comparisons and representative multi-batch/tail measurements.
